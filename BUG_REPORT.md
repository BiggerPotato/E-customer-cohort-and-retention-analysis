# Bug Report

Findings below come from the baseline test run and review of the actual analysis/dashboard code. The three baseline failures were reproduced by `python -m unittest -v test_retention_analysis.py`; all reported fixes were then covered by passing regression/browser tests.

| Bug ID | Description and reproducible steps | Expected vs actual before fix | Severity | Priority | Status / verification |
|---|---|---|---|---|---|
| BUG-001 | Cancellation detection was case-sensitive and did not trim invoice IDs. Run `test_lowercase_cancelled_invoice_is_removed` with `c1001`, or `test_spaced_cancelled_invoice_is_removed` with ` C1001`. | Expected cancelled invoice rows to be excluded; actual cleaner kept them. | Major data-quality defect | P1 | Resolved in `retention_helpers.py` by trimming and case-normalizing invoice IDs. Regression cases pass. |
| BUG-002 | Positive infinity passed the `price > 0` check. Run `test_infinite_price_is_removed` with `UnitPrice=inf`. | Expected non-finite price to be rejected; actual cleaner retained the row. | Major data-quality defect | P1 | Resolved by checking finite price and quantity values before positivity. Regression case passes. |
| BUG-003 | `retention_analysis.py` repeated cleaning after calling `clean_transactions`, so the script and the tested helper could diverge. | Expected one shared validation path; actual script had a second, weaker filter. | Moderate maintainability/data-consistency risk | P2 | Resolved: the script now uses the helper result directly and calculates revenue through the shared helper. Full-program system test passes. |
| BUG-004 | Dashboard cohort parser recognized tidy period/value tables but not the project's wide CSV with numeric headers `0`, `1`, … | Expected an interactive cohort heatmap from `cohort_retention.csv`; actual browser displayed a format warning and relied on the PNG fallback. | Moderate UI/coverage defect | P2 | Resolved: numeric month columns now render as an interactive heatmap. Playwright cohort test passes. |
| BUG-005 | Dashboard did not recognize the actual source filename `Online Retail.csv` or the camel-case `InvoiceNo` header. | Expected source-based customer/repeat/order-gap metrics; actual dashboard showed unavailable values. | Moderate UI/data presentation defect | P2 | Resolved: loader recognizes the actual file and source headers; Playwright fixture verifies calculated metrics and a separate browser check matches actual CSV orders/revenue to the monthly summary. |
| BUG-006 | Python test-result UI appended the method name twice to the qualified unittest name. | Expected one readable case identifier; actual list repeated the method suffix. | Minor presentation defect | P3 | Resolved in `dashboard_server.py`; current results use the qualified name once. |
| BUG-007 | The dashboard loaded the combined `retention_analysis.png` in the Days between orders panel, so that panel also showed the monthly revenue plot. | Expected the monthly chart in its own card and only the order-gap plot in the days section; actual combined image contained both plots. | Moderate UI presentation defect | P2 | Resolved: analysis now also creates `days_between_orders.png`, and the dashboard uses that dedicated image. Playwright checks the image source and visible monthly-canvas pixels. |

## Status note

The invoice/price defects were observed as three failing test cases (case-sensitive invoice, whitespace invoice, and infinite price). The corrected behavior was verified in the subsequent regression run. The wrong-chart placement was reproduced from the provided screenshot and guarded by browser assertions. No unresolved failures remain in the latest recorded run; see `TEST_SUMMARY.md`.
